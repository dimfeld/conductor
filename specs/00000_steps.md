Below is a detailed, step-by-step blueprint for building a locally-hosted web tool designed to build context for a Large Language Model (LLM) using Svelte 5, SvelteKit, shadcn-svelte, and Tailwind. The tool integrates with `repomix`, `ripgrep`, and `jujutsu (jj)` for context generation and version control, watches the filesystem for changes, and updates the UI in real-time. Following the blueprint, I’ll break it into small, iterative chunks that build on each other, refine those chunks into appropriately sized steps, and ensure each step is detailed enough for an engineer to implement with strong testing, even without prior context.

---

## Detailed Step-by-Step Blueprint

### Project Overview
The project is a web-based tool running locally, enabling users to:
- Select files via a tree view, globs, or package dependencies.
- Apply `ripgrep` expressions for filtering.
- Generate context using `repomix`, incorporating rules from `.mdc` files, a task description, and an optional formatting prompt.
- Manage version control with `jujutsu (jj)`, including workspace switching, diffs, and commits.
- Persist settings per workspace in `.conductor.yaml`.
- Update the UI in real-time as the filesystem changes.

### High-Level Components
1. **Frontend (UI):**
   - Top navigation with workspace dropdown and tabs (Context Builder, Diff).
   - Context Builder tab: Tree view, input fields (globs, grep expressions, task description), package selection, checkboxes (formatting prompt, rules), and a "Generate Context" button.
   - Diff tab: Side-by-side diff view, commit message field, and "Commit" button.

2. **Backend:**
   - File system interaction: Read directory structure, watch for changes, and stream updates via Server-Sent Events (SSE).
   - Integration with external tools: `repomix` for context generation, `ripgrep` for file filtering, `jj` for version control.
   - Settings management: Save/load to/from `.conductor.yaml`.

3. **Workflow:**
   - Users select files and configure inputs.
   - The tool aggregates files, applies grep filters, runs `repomix`, adds rules/task/prompt, and copies the context to the clipboard.
   - Users manage workspaces and commits via `jj`.

### Blueprint Steps
1. **Setup Environment:**
   - Initialize a SvelteKit project with Svelte 5.
   - Install and configure shadcn-svelte and Tailwind CSS for styling.

2. **Build UI Foundation:**
   - Create a top navigation bar with a workspace dropdown and tabs.
   - Set up placeholder pages for Context Builder and Diff tabs.

3. **Implement File Selection:**
   - Develop a collapsible tree view with checkboxes to select files/directories.
   - Populate it with the project’s directory structure.
   - Manage selection state.

4. **Add Input Controls:**
   - Add text inputs for globs, independent grep, tree view grep, and task description.
   - Include a checkbox for including a formatting prompt.
   - Add a package dependencies list with checkboxes.
   - Add a "Generate Context" button.

5. **Integrate Version Control:**
   - Enable workspace management (list, switch, create) using `jj`.
   - Auto-create bookmarks for new workspaces.
   - Build a diff view with `jj diff` output, commit message input, and commit functionality.

6. **Enable Real-Time Updates:**
   - Watch the filesystem for changes.
   - Stream updates to the frontend via SSE.
   - Reflect changes in the tree view dynamically.

7. **Handle Rules Processing:**
   - Parse `.mdc` files for rules and their conditions.
   - Automatically include rules based on conditions.
   - Provide a UI for manual rule selection.

8. **Generate Context:**
   - Aggregate files from tree view, globs, and package directories.
   - Apply `ripgrep` for filtering.
   - Run `repomix` on the file list.
   - Combine rules, task description, and formatting prompt into the final context.
   - Copy the context to the clipboard.

9. **Persist Data:**
   - Save settings (e.g., selections, inputs) to `.conductor.yaml` per workspace.
   - Load settings when switching workspaces.

## Refined Steps with Detailed Instructions

After reviewing the chunks, they’re broken into steps small enough for safe implementation and testing, yet large enough to advance the project meaningfully. Each step includes detailed instructions for an engineer unfamiliar with prior discussions.

### 1. Basic SvelteKit Setup with UI Skeleton
- **Objective:** Establish the project foundation with a basic UI structure.
- **Steps:**
  - **1.1: Initialize SvelteKit Project**
    - Run `npm create svelte@latest my-project` in the terminal, select SvelteKit, enable TypeScript, and include default options (e.g., ESLint, Prettier).
    - Install dependencies with `npm install`.
    - Verify the skeleton app runs with `npm run dev` and opens at `http://localhost:5173`.
  - **1.2: Integrate shadcn-svelte and Tailwind**
    - Install Tailwind: `npm install -D tailwindcss postcss autoprefixer`, then run `npx tailwindcss init -p`.
    - Configure `tailwind.config.js` to include Svelte files (`content: ['./src/**/*.{svelte,js,ts}']`).
    - Add Tailwind directives to `src/app.css` (`@tailwind base; @tailwind components; @tailwind utilities;`).
    - Install shadcn-svelte: Follow its setup guide (e.g., `npx shadcn-svelte init`), ensuring components like buttons and dropdowns are available.
    - Test by adding a Tailwind-styled `<div class="bg-blue-500 p-4">Test</div>` to `src/routes/+page.svelte` and confirming it renders.
  - **1.3: Create Navigation and Tabs**
    - In `src/lib`, create `Navigation.svelte`: Use shadcn-svelte’s `DropdownMenu` for a workspace dropdown (placeholder items: "Workspace 1", "Workspace 2") and `Tabs` for "Context Builder" and "Diff".
    - In `src/routes/+layout.svelte`, include `<Navigation />` above the `{@render children()}`.
    - Create `src/routes/context/+page.svelte` and `src/routes/diff/+page.svelte` with placeholder text (e.g., "Context Builder Tab", "Diff Tab").
    - Test: Navigate to `/context` and `/diff`, ensuring tabs switch and the dropdown renders.
- **Testing:** Run `npm run dev`, verify the app loads, navigation appears, and tabs switch without errors.

### 2. Tree View Implementation
- **Objective:** Enable file selection via a tree view.
- **Steps:**
  - **2.1: Build Tree View Component**
    - Create `src/lib/TreeView.svelte` using shadcn-svelte’s `Collapsible` for nested directories and `Checkbox` for selections.
    - Define a recursive component structure: Each node has a name, checkbox, and optional children.
    - Test by hardcoding a sample structure (e.g., `{ name: "src", children: [{ name: "lib" }] }`) and confirming it renders with collapsible nodes and functional checkboxes.
  - **2.2: Populate with Directory Structure**
    - In `src/routes/context/+page.server.ts`, create a `load` function using `fs.promises.readdir` to recursively read the project directory (relative to the project root).
    - Return a tree structure (e.g., `{ name: "root", children: [...] }`) as `data.tree`.
    - In `src/routes/context/+page.svelte`, pass `data.tree` to `<TreeView tree={data.tree} />`.
    - Test: Ensure the tree reflects the actual directory structure (e.g., `src`, `node_modules`).
  - **2.3: Manage Selection State**
    - In `TreeView.svelte`, use a Svelte store (`writable<Set<string>>`) to track selected file paths.
    - Update the store on checkbox changes, storing full paths (e.g., `src/lib/file.js`).
    - Test: Select/deselect nodes, log the store, and verify it updates accurately.
- **Testing:** Confirm the tree displays the filesystem, collapses/expands, and selections persist across interactions.

### 3. Inputs and Controls
- **Objective:** Add UI controls for context configuration.
- **Steps:**
  - **3.1: Add Input Fields**
    - In `src/routes/context/+page.svelte`, create a form with shadcn-svelte `Input` components for:
      - Globs (e.g., `*.ts`)
      - Independent grep (e.g., `TODO`)
      - Tree view grep (e.g., `function`)
      - Task description (textarea).
    - Use Svelte stores to manage input values (e.g., `writable('')` for each).
    - Test: Type values and log the stores to verify updates.
  - **3.2: Add Checkboxes and Button**
    - Add a shadcn-svelte `Checkbox` labeled "Include Formatting Prompt" with a `writable(false)` store.
    - Below inputs, add a `Button` labeled "Generate Context" (no action yet).
    - Test: Toggle the checkbox and click the button, ensuring state changes and no errors occur.
  - **3.3: Add Package Dependencies List**
    - In `+page.server.ts`, read `package.json` (or `pnpm-workspace.yaml` if using pnpm) to list dependencies or workspaces.
    - Return as `data.packages` (e.g., `[{ name: "svelte", dir: "node_modules/svelte" }]`).
    - In `+page.svelte`, render a list of `Checkbox` components for each package, tied to a `writable<Set<string>>` store.
    - Test: Verify packages render and selections update the store.
- **Testing:** Ensure all inputs update their stores, checkboxes toggle, and the button renders.

### 4. Workspace Management
- **Objective:** Integrate `jj` for workspace management.
- **Steps:**
  - **4.1: List and Switch Workspaces**
    - In `src/lib/jj.ts`, create a function `listWorkspaces()` to run `jj workspace list` via `child_process.spawnSync`, parsing output into `{ name: string }[]`.
    - In `Navigation.svelte`, update the dropdown to use `listWorkspaces()` data.
    - Add an action to switch workspaces with `jj workspace use <name>` on selection.
    - Test: Run in a `jj`-initialized repo, confirm workspaces list and switching works (reload page to verify).
  - **4.2: Create New Workspaces**
    - Add a "New Workspace" dropdown item triggering a form (e.g., shadcn-svelte `Dialog` with a name input).
    - On submit, run `jj workspace add <name>` and refresh the dropdown.
    - Test: Create a new workspace, verify it appears and can be switched to.
  - **4.3: Auto-Create Bookmarks**
    - In the create function, after `jj workspace add`, run `jj bookmark create <name>-start`.
    - Test: Create a workspace, check `jj bookmark list` to confirm the bookmark exists.
- **Testing:** Initialize a `jj` repo, test listing, switching, and creating workspaces with bookmarks.

### 5. Diff Tab Implementation
- **Objective:** Build version control UI with `jj`.
- **Steps:**
  - **5.1: Display Diff View**
    - In `src/routes/diff/+page.server.ts`, run `jj diff` and return the output as `data.diff`.
    - In `+page.svelte`, use a side-by-side layout (e.g., two `<pre>` tags with Tailwind `grid`) to display `data.diff`.
    - Test: Make a change in the repo, visit `/diff`, and verify the diff appears.
  - **5.2: Add Commit UI**
    - Below the diff, add a shadcn-svelte `Textarea` for the commit message and a `Button` labeled "Commit".
    - Use stores for the message.
    - Test: Type a message and confirm the store updates.
  - **5.3: Execute Commit**
    - On button click, run `jj commit -m <message>` via `child_process.spawnSync`.
    - Display success/error via shadcn-svelte `Toast`.
    - Test: Commit a change, verify `jj log` reflects it, and check toast feedback.
- **Testing:** Modify a file, view the diff, commit it, and confirm the change is recorded.

### 6. File Watching and SSE
- **Objective:** Enable real-time tree view updates.
- **Steps:**
  - **6.1: Setup File Watcher**
    - In `src/lib/fileWatcher.ts`, use `chokidar` (`npm install chokidar`) to watch the project root (`chokidar.watch('.')`).
    - Log events (add, change, unlink) to confirm watching works.
  - **6.2: Implement SSE**
    - Create `src/routes/api/file-events/+server.ts` with an SSE endpoint:
      ```ts
      export async function GET() {
        const stream = new ReadableStream({
          start(controller) {
            watcher.on('all', (event, path) =>
              controller.enqueue(`data: ${JSON.stringify({ event, path })}\n\n`)
            );
          }
        });
        return new Response(stream, {
          headers: { 'Content-Type': 'text/event-stream' }
        });
      }
      ```
    - Test: Fetch `/api/file-events` with a tool like `curl` and modify a file to see events.
  - **6.3: Update Tree View**
    - In `TreeView.svelte`, connect to `/api/file-events` with `EventSource`.
    - On events, refresh the tree by re-fetching from `+page.server.ts` or updating locally.
    - Test: Add/remove files, confirm the tree updates in real-time.
- **Testing:** Watch the directory, change files, and verify the tree reflects updates instantly.

### 7. Parse `.mdc` Files
- **Objective:** Extract rules from `.mdc` files.
- **Steps:**
  - **7.1: Implement Parser**
    - In `src/lib/rules.ts`, create `parseMdcFiles()` to find `*.mdc` files (e.g., via `glob`) and parse them.
    - Assume `.mdc` is YAML with `{ rule: string, condition: string }`; return `{ rule: string, condition: string }[]`.
    - Test: Create a sample `.mdc` file, log the parsed output.
- **Testing:** Place `.mdc` files in the project, confirm parsing matches their content.

### 8. Automatic Rule Inclusion
- **Objective:** Auto-select rules based on conditions.
- **Steps:**
  - **8.1: Evaluate Conditions**
    - In `rules.ts`, add `autoIncludeRules(rules, context)` to evaluate conditions (e.g., `condition: "file:src/*.ts"` checks if such files are selected).
    - Return `{ rule: string }[]`.
    - Test: Pass sample rules and context, verify correct rules are included.
- **Testing:** Simulate contexts, confirm condition-based inclusion works.

### 9. Manual Rule Selection UI
- **Objective:** Allow manual rule selection.
- **Steps:**
  - **9.1: Render Rule Checkboxes**
    - In `+page.svelte`, list rules from `parseMdcFiles()` with `Checkbox` components.
    - Use a `writable<Set<string>>` store for selected rules.
    - Test: Toggle checkboxes, verify the store updates.
- **Testing:** Display rules, select/deselect, and confirm state persists.

### 10. File Selection Aggregation
- **Objective:** Combine all file selections.
- **Steps:**
  - **10.1: Aggregate Files**
    - In `src/lib/context.ts`, create `aggregateFiles(treeSelections, globs, packages)`:
      - Add `treeSelections` (from TreeView store).
      - Parse `globs` with `glob` (`npm install glob`) and add matches.
      - Add package directories from the packages store.
    - Return a deduplicated `string[]` of file paths.
    - Test: Pass sample inputs, log the file list.
- **Testing:** Select files, globs, and packages; verify the combined list is correct.

### 11. Grep Processing
- **Objective:** Filter files with `ripgrep`.
- **Steps:**
  - **11.1: Run Grep**
    - In `context.ts`, add `grepFiles(files, independentGrep, treeGrep)`:
      - Run `rg <independentGrep> .` for all files.
      - Run `rg <treeGrep>` on `files` from tree view.
      - Parse outputs to a `string[]` of matching files.
    - Test: Run with sample greps, confirm matches.
- **Testing:** Apply grep expressions, verify filtered file list.

### 12. Run `repomix`
- **Objective:** Generate context with `repomix`.
- **Steps:**
  - **12.1: Execute repomix**
    - In `context.ts`, add `runRepomix(files)` to run `repomix` (`npm install repomix`) with the file list and read its output file.
    - Handle errors with a fallback message.
    - Test: Pass a file list, verify output content.
- **Testing:** Run `repomix` on sample files, check output file exists and is readable.

### 13. Concatenate Components
- **Objective:** Build the final context.
- **Steps:**
  - **13.1: Combine Components**
    - In `context.ts`, add `buildContext(repomixOutput, rules, task, includePrompt)`:
      - Concatenate rules (auto + manual), task, and `repomixOutput`.
      - If `includePrompt`, prepend a formatting prompt (e.g., "Format as markdown").
    - Return a single string.
    - Test: Pass sample inputs, log the result.
- **Testing:** Combine components, verify the output string matches expectations.

### 14. Copy to Clipboard
- **Objective:** Copy context to clipboard.
- **Steps:**
  - **14.1: Implement Copy**
    - In `+page.svelte`, on "Generate Context" click, call `navigator.clipboard.writeText(context)` with the final context.
    - Show a `Toast` on success/error.
    - Test: Click the button, paste elsewhere to confirm.
- **Testing:** Generate context, verify it’s copied and toast appears.

### 15. Data Persistence
- **Objective:** Save/load settings per workspace.
- **Steps:**
  - **15.1: Save and Load Settings**
    - In `src/lib/settings.ts`, create `saveSettings(workspace, settings)` to write to `.conductor.yaml` in the workspace root using `js-yaml`.
    - Add `loadSettings(workspace)` to read it.
    - Include all stores (selections, inputs) in settings.
    - Hook into workspace switching and context generation to load/save.
    - Test: Switch workspaces, generate context, verify settings persist.
- **Testing:** Save settings, switch workspaces, confirm they reload correctly.
